Do banco local para uma API de tarefas

A Aula 3 provou que o SQLite guarda uma tarefa. Agora o servidor HTTP passará a receber pedidos, validar dados e devolver respostas JSON para que uma interface possa usar as tarefas depois.

Objetivo

Implementar as rotas GET /tasks, POST /tasks e PATCH /tasks/:id. Ao final, o terminal poderá criar, listar e alterar o status de uma tarefa por HTTP.

Conceitos novos

ConceitoSignificado
API HTTPContrato pelo qual outro programa pede ou altera dados.
RotaCombinação de método e caminho, como POST /tasks.
JSONFormato de texto estruturado usado no corpo das requisições e respostas.
ValidaçãoChecagem dos dados antes de escrever no banco.
Status HTTPCódigo que comunica o resultado: 200, 201, 400 ou 404.
Teste automatizadoPrograma que executa uma verificação repetível sem inspeção manual.

 data/foco-ai.db

Não enviaremos SQL pela internet. O servidor aceita apenas dados simples, valida-os e chama funções específicas do módulo do banco.

Resultado observável

Com npm run dev ativo, curl http://localhost:3000/tasks retornará JSON. Ao enviar um POST, uma tarefa nova será gravada e aparecerá no próximo GET.

Fora de escopo

Interface visual, autenticação, usuários, exclusão de tarefas e IA. A interface consumirá essa API na Aula 5.

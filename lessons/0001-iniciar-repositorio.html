Transforme esta pasta em um repositório publicável

Ao terminar, o projeto terá um histórico Git local, um repositório remoto no GitHub e um primeiro commit. Esta é a base para branches, pull requests, rebase e worktrees nas próximas aulas.

Vitória desta aula: git status mostrará working tree clean, e a página do GitHub exibirá o commit inicial.

Antes de começar

Você está na pasta minicurso-dev. Ela contém os materiais do curso e será a raiz do FocoAI. As ferramentas já foram verificadas: Git 2.53, Node 26.7, npm 11.19 e VS Code 1.139.

Faça agora

  1. Abra a pasta correta e o terminal integrado do VS Code. Primeiro, veja o nome da pasta na barra superior do VS Code: ele deve incluir minicurso-dev. Se estiver em outra pasta, clique em Arquivo → Abrir Pasta..., navegue até D:\OneDrive\André Serra\01 Projetos\minicurso-dev e clique em Selecionar Pasta. Depois clique em Terminal → Novo Terminal. Alternativa: pressione Ctrl+`; a tecla de crase fica normalmente à esquerda do número 1. O painel Terminal abrirá na parte inferior. Digite cada comando abaixo e pressione Enter após cada um:
    pwd
git status
    Resultado esperado de pwd: um caminho terminado em /01 Projetos/minicurso-dev ou \01 Projetos\minicurso-dev. Resultado esperado de git status: uma mensagem dizendo que esta ainda não é um repositório Git. Se pwd terminar em outra pasta, clique em Terminal → Kill Terminal, abra a pasta indicada acima e crie um novo terminal.
  2. Confira a identidade que aparecerá nos commits.
    git config --global user.name
git config --global user.email
    Se algum comando não imprimir valor, configure-o antes de continuar:
    git config --global user.name "Seu Nome"
git config --global user.email "seu-email@example.com"
    Use o e-mail que você quer associar à sua conta do GitHub.
  3. Crie o repositório local e fixe o nome da branch principal.
    git init -b main
git status
    Agora o VS Code deve mostrar o ícone de Source Control com mudanças não rastreadas.
  4. Crie os dois arquivos que não devem faltar. No Explorer do VS Code, crie README.md com este conteúdo:
    # FocoAI

Um organizador de tarefas com SQLite e IA.

## Como executar
Em construção durante o minicurso.
    Crie também .gitignore com:
    node_modules/
.env
*.db
*.sqlite
.DS_Store
    Por quê: dependências, chaves e bancos locais não pertencem ao histórico compartilhado.
  5. Faça o primeiro commit. Revise antes de gravar:
    git status
git add README.md .gitignore MISSION.md RESOURCES.md NOTES.md IDEA.md assets lessons reference
git commit -m "chore: iniciar curso e repositório do FocoAI"
git log --oneline -1
    O último comando deve mostrar um hash curto e a mensagem do commit.
  6. Crie o repositório remoto no GitHub. No navegador, entre em github.com/new. Defina o nome foco-ai, escolha a visibilidade que preferir e não marque README, .gitignore nem licença. Criar esses arquivos no remoto agora produziria dois históricos iniciais desnecessários.
  7. Conecte e envie o histórico. Copie a URL HTTPS exibida pelo GitHub e substitua apenas o trecho entre sinais de menor/maior:
    git remote add origin <URL-HTTPS-DO-SEU-REPOSITORIO>
git remote -v
git push -u origin main
    Na primeira vez, o GitHub pode pedir autenticação no navegador. Conclua-a; não cole tokens no terminal ou em arquivos do projeto.
  8. Verifique no navegador e no VS Code. Atualize a página do repositório no GitHub. Depois rode:
    git status
git branch -vv
    O estado deve estar limpo e main deve rastrear origin/main.

Checagem de recuperação

Por que o README não foi criado pelo GitHub nesta aula?

Porque já existe um histórico local. Criar um commit inicial também no remoto criaria duas pontas que teríamos de reconciliar. O remoto vazio recebe a história local diretamente.

O que -u faz em git push -u origin main?

Define origin/main como upstream de main. Depois disso, git push e git pull sabem qual branch remota usar.

Por que .env está no .gitignore?

Ele será usado mais tarde para a chave da API. Uma chave publicada no GitHub deve ser considerada comprometida e revogada.

Se algo der errado

remote origin already exists: rode git remote set-url origin <URL-HTTPS>, confira com git remote -v e repita o push.

src refspec main does not match any: ainda não existe commit. Execute a etapa 5 e tente novamente.

Autenticação falhou: execute git push -u origin main de novo e conclua a janela de login do GitHub. Não use sua senha do GitHub como token.

Git: primeiros comandos e sinais

Consulte durante a Aula 1. Cada item diz o que digitar, o que cada parte significa e qual resultado procurar.

Iniciar um repositório

git init -b main
ParteSignificado
gitO programa de controle de versão.
initInicializa um repositório Git na pasta em que o terminal está aberto.
-bAbreviação de branch: informa o nome da branch inicial.
mainO nome escolhido para essa primeira branch.

Resultado esperado: uma mensagem contendo Initialized empty Git repository. Depois, git branch --show-current deve mostrar main.

Ver o estado atual

git status

Mostra a branch atual e separa arquivos em três grupos: modificados mas não preparados, preparados para commit e ainda não rastreados. Rode antes de add, antes de commit e quando não souber onde está.

Preparar arquivos

git add README.md .gitignore

add coloca uma cópia atual dos arquivos indicados na área de preparação (staging area). Isso ainda não cria um commit. Para conferir, rode git status; os arquivos devem aparecer em verde, em “Changes to be committed”.

Criar um commit

git commit -m "chore: iniciar curso e repositório do FocoAI"
ParteSignificado
commitGrava no histórico as mudanças que estão na área de preparação.
-mAbreviação de message: fornece a mensagem do commit no próprio comando.
Texto entre aspasDescrição curta da mudança. As aspas mantêm toda a frase como uma única mensagem.

Sem -m, o Git abriria um editor para que você escrevesse a mensagem. Resultado esperado: uma linha com a branch, um hash curto e a mensagem do commit.

O aviso LF/CRLF

warning: in the working copy of 'README.md', LF will be replaced by CRLF

É um aviso de formato de quebra de linha, não uma falha. LF usa apenas \n e é comum em Linux/macOS. CRLF usa \r\n e é comum no Windows. Com a configuração usual do Git no Windows, o repositório mantém uma forma padronizada e a cópia local pode usar CRLF.

O que fazer: se você não mudou apenas as quebras de linha de propósito, continue com o comando que estava executando. O conteúdo legível do arquivo não foi alterado.

Diagnóstico em 30 segundos

  1. Digite pwd. Confirme que o terminal está em minicurso-dev.
  2. Digite git status. Leia a seção que lista seus arquivos.
  3. Se houver um aviso LF/CRLF ao executar git add, continue.
  4. Antes de git commit, confirme uma última vez com git status.

Fonte oficial: git init, git add, git commit e git status.
